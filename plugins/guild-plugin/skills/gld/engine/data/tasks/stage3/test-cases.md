**Bug Issues** (`type: bug` in `analysis.md`): the first cases are the regression cases — the behaviour the bug breaks, stated as the correct result. Tag each with `(regression)` before its AC tag: `- C1: saving with an empty title shows the validation message. (regression) (AC #1)`. The developer turns them into a test that must fail on today's code, so describe the observable result the bug violates, precisely enough that a test written from it fails for the bug's reason and for nothing else.

**Refactor Issues** (`type: refactor`): behaviour does not change, so the cases state what must stay true — the existing suites that must stay green (name them: `- C1: the settings screen tests stay green. (AC #1)`), the observable results the structure change must keep, and the structural goal as a checkable case when an acceptance criterion states one (which module no longer imports which). The `(safety net)` cases above are the behaviour a new net pins before the transform.
