The checks this step must give are the ones listed under "Required checks" below; besides `design-conformance` they may be:
- `root-cause-addressed` (bug template, against `diagnosis.md` instead of a skeleton) — `pass` when the change fixes the cause the diagnosis names (or a cause it shows to be the real one), not only the symptom, and the blast radius the diagnosis lists stays safe; `fail` when it hides the failure (a guard, catch, retry or special case around the symptom) or changes a dependent behaviour the Issue did not ask for. `repro-evidence.md` shows how the regression test failed before the fix.
- `structure-improved` (refactor templates, against `skeleton.md` as the target structure) — `pass` when the code really moved toward the target structure; `fail` for churn (renames and moves without a better structure) or a target left half-done.
- `behavior-preserved` (refactor templates) — `pass` when no observable behaviour changed: same outputs, errors, side effects, public API and user-visible result; `fail` when any did — name the file, line and the behaviour.
