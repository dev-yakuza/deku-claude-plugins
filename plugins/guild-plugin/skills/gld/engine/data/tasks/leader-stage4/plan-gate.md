**A bug Issue keeps its reproduction** (readiness E4). When the Issue carries a bug label, or an analysis of this Issue recorded `type: bug`, the engine treats it as a bug Issue: its plan must be a template with a `repro-red` step (the failing test is red on the code before the fix). If the analysis now offers only a template without one (for example `safety-net` because the analysis was switched to `refactor` / `safety_net: only`), the engine removes `plan` (`allowed.narrowed` names `bug-without-repro-red`). Do not steer the analysis toward another type to get around it. If you believe the bug is already fixed, or the Issue's premise is wrong, that is a human's decision: `escalate` with the evidence in `note` and a `recommendation` (`close-as-decided` when it is fixed already, or `plan` with the template you would accept). If the analysis mis-set the type of a real bug, `rerun analyze` and say so. A plan that takes a bug Issue onto a template without `repro-red` is refused by the engine and handed to a human.
