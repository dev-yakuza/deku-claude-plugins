- **Mutations (optional).** When an acceptance criterion says that a test must *fail* once some code is removed or changed ("without this flag the test is red", "proven by mutation"), do not report a run of your own — nobody can use it as proof. Declare the mutation and commit it with your work in `mutations.json` in this Issue's `docs/specs/` folder (next to `analysis.md`); the engine applies it to a fresh tree of the final HEAD, runs the repository's `test` command itself before the done gate and gives the leader what it saw:

  `{"format": 1, "mutations": [{"acs": [2], "path": "lib/quiz/stroke.dart", "find": "showHint: true", "replace": "showHint: false", "note": "AC 2: without the hint flag the stroke test is red"}]}`

  `acs` are AC numbers of `analysis.md`. `path` is a tracked production file — never a test, a golden, a test or CI configuration, or a file under `docs/specs/`. `find` is literal text that occurs exactly once in that file at the end of the work (whitespace counts; take enough of the line); `replace` is what stands in its place (`""` removes it). At most 5 entries; every entry costs a whole `test` run, so declare only what a criterion asks for, and make it the change the criterion names — code that no longer compiles, or a change that breaks everything, proves nothing. A later change of that line makes the entry unusable: keep the file right when you edit the code. No such criterion → no file. A wrong entry never fails your step; it is only no proof.
- **A frozen test a human allowed.** When `leader-decision.md` holds a human's decision that names existing test files you may change, change only the content of exactly those files and only as that decision says — do not delete, rename or move them. Every other existing test file stays frozen.
