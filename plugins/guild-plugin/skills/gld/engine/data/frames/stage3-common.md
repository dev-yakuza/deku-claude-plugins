## Stage-3 result rules (they replace the `requests` sentence of rule 7)

10. **Step requests.** `requests[].step` is a step of the plugin step catalog — the schema lists the names; nothing else, never a command. `op: add` asks for that step: the engine adds it by itself after this step is done (where it goes is fixed by the step's class), declines it when its role cannot run in this repository or this Issue already has the most added steps, and records the outcome. Ask only for a concrete reason in this Issue — the `trigger` code names it, `note` says where (file, screen, text) in one line; every added step is a session. A request from the analysis goes to the plan gate, which decides. `op: remove` / `skip` names a catalog step already in the procedure that is no longer needed; the leader decides. A step of the template itself cannot be removed. The catalog:
{catalog}
11. **Blocking discoveries.** `blocks_current_ac: true` marks a discovery this Issue's acceptance criteria cannot be met without. The engine acts on it: before the developer step is done the developer gets it to fix, after that the engine adds a fix step — and the leader checks every such fix at the end, because your word alone widened the scope. Set it only when that is true (name the criterion in `note`); everything else is `false` and becomes a follow-up candidate.
12. **Security discoveries.** A `kind: security` discovery is never written into the pull request: in a private repository it becomes a follow-up Issue with a security label, in a public one it stays in the engine's local record for a human. Write `where` and `note` plainly for that human, never a real secret — say where it is.
13. **Irreversible changes.** `irreversible` lists every change this step made — or, for an analysis, that the Issue needs — that cannot simply be reverted after the merge or that acts outside this repository, each with its code, `where` (file or system) and a one-line `note`: `deploy-or-release`, `external-api-effect`, `shared-db-execution`, `iac-apply`, `resource-deletion` (an effect outside the repository); `destructive-migration`, `data-transform`, `breaking-api`, `storage-format-change`, `major-dependency-upgrade` (hard to revert); `migration-file` (a migration a human runs). Report what is there, not to be safe and not to get past anything: a report only ever makes the engine stop for a human or tell one. Empty list when there is none.
